# UI Prototyping Skills — Initial Vision

**Captured**: 2026-10-26
**Captured by**: Adam Wang (via OpenClaw assistant conversation)

## Raw Ask

I want to build a set of AI skills for UI prototyping along with my existing analysis skills. So I can use the AI prototype to discuss requirements, ideas, designs with stakeholders. I would like to generate a set of UI design documents that can be used for future development. Also, if I have a UI design specification, I can import it for the UI prototype to follow.

## Key Elements Identified

1. **New UI prototyping skill set** — sits alongside (not replacing) the existing analysis skill set (requirements, goals, W5H, domain modeling, diagrams, planning)
2. **Conversational prototyping** — the AI prototype itself should be usable as a discussion tool with stakeholders about requirements, ideas, and designs (not just a one-shot generator)
3. **Forward output** — generates UI design documents intended to be consumed by future development work (screen specs, wireframes, flows, design artifacts that downstream coding/design work can use)
4. **Reverse input (import path)** — if a UI design specification already exists (e.g., from a designer, a Figma export, an existing style guide), the skill set should be able to import it and have the prototype follow/conform to it, rather than only generating from scratch
5. **Traceability** — implied by "along with my existing analysis skills" — should connect back to requirements/domain model, consistent with how every other EDPS skill maintains traceability
